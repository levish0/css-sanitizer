# 2026-06-26 0.2.0 deny-by-default redesign

## Objective
- Close the audited security gaps and make completeness a library guarantee rather
  than relying on policy authors. User explicitly chose: **full deny-by-default**
  policy interface + ship a built-in `StrictPolicy` preset. Bumped to 0.2.0.

## User-Approved Scope
- "정책이 깜빡하면 안 됨" → forgetting a hook must never leak → deny-by-default on the
  whole policy surface (option A over the lighter neutral-trait variant).
- Provide a vetted built-in `StrictPolicy` allowlist.
- Long-term/proper fix over minimal patch; hybrid architecture (keep explicit
  contextual traversal, add Visit-based value guard + Visit-oracle completeness test).
- Version bump to 0.2.0 with CHANGELOG migration notes.

## Implementation Status
- Completed: all 7 planned tasks. Tests/clippy/fmt green.

## Major Changes
- `src/policy.rs`: all content-admitting hooks now default `NodeAction::Drop`
  (visit_rule, visit_selector_list + selector hooks, visit_property + per-location
  hooks, 3 descriptor hooks). Descent-gate rule hooks (page/counter-style/viewport/
  font-feature-values, page-margin, font-feature subrule) stay `Continue`. Added
  `ValueAction`/`ValueContext`/`ValueLocation`, value hooks `check_url`/`check_variable`/
  `check_environment_variable`/`check_token` (default `Deny`), and `visit_scope_selectors`.
- `src/guard.rs` (new): `ValueGuard` lightningcss `Visitor` (URLS|IMAGES|VARIABLES|
  ENVIRONMENT_VARIABLES|TOKENS) with `Denied` sentinel + `?` short-circuit. 4 monomorphic
  wrappers (Property + 3 descriptor types). `visit_token` routes Url/Var/Env to the right
  check; everything else → `check_token`. **`visit_image` manually recurses image-set**
  because `ImageSetOption.image` is `#[skip_type]` in lightningcss (excluded from
  CHILD_TYPES → derive pruning would skip image-set urls). This is the one structural
  value gap that the derive traversal misses; all other `skip_type` fields don't carry
  fetchable urls and var/url elsewhere force the unparsed-token path.
- `src/options.rs` (new): `SanitizeOptions { max_depth=256, enforce_value_guard=true }`
  (`#[non_exhaustive]` + `with_*` setters).
- `src/sanitize.rs`: rewritten around `Engine { policy, opts }`. Depth cap (fail-closed
  `rules.clear()` when `depth > max_depth`) at `sanitize_rule_list` entry. `@scope`
  `scope_start`/`scope_end` now sanitized via `SelectorLocation::Scope`. Value guard run
  after each kept property/descriptor (Skip bypasses guard by design). Added 4
  `*_with_options` fns; old 4 fns are wrappers.
- `src/preset.rs` (new): public `StrictPolicy` allowlist builder (allow_properties/
  allow_rules/allow_values/allow_important/allow_url/allow_var/allow_env). Storage is
  `String` (not `&'static`). `matches_allowed_value` compares `value_to_css_string`
  (lifetime-safe). `check_token` denies raw url tokens (gated by allow_url) and
  `expression()`, allows other tokens (recursion catches nested url/var/env).
- `src/lib.rs`: module wiring + re-exports + deny-by-default doctests.
- Tests: `tests/oracle.rs` (Visit-oracle differential completeness),
  `tests/regression_tests.rs` (scope prelude, font-face url default-deny, custom-prop
  url backstop, depth cap, guard toggle). `tests/common/mod.rs` re-exports library
  StrictPolicy, `FunctionSecurityPolicy = StrictPolicy` alias, allowlist-shaped demo
  policies. `examples/sanitize_strings.rs` + `benches/sanitize.rs` updated for the new
  model (added visit_selector_list / value hooks).
- `Cargo.toml` 0.1.4 → 0.2.0. `CHANGELOG.md` 0.2.0 entry. README rewritten.

## Remaining Work
- Known gaps: `skip_type` audit was reasoned, not exhaustively fuzzed — only image-set is
  handled explicitly. If a future lightningcss adds a url-bearing `skip_type` field, the
  oracle test (urls compared) should catch it. Container/supports condition declarations
  still not traversed (non-rendered; low risk, documented boundary).
- Risks: `StrictPolicy` allows all selectors (no selector filtering) by design — selector
  scoping is the caller's job.
- Next entry points: consider a selector-completeness oracle assertion; consider exposing
  a `check_function` hook if blanket function policy is ever needed.

## Notes For Next Agent
- The whole safety model rests on two guarantees: deny-by-default structural hooks +
  engine-enforced value guard. Do not reintroduce fail-open defaults.
- The image-set `visit_image` override in `guard.rs` is load-bearing — do not "simplify"
  it to the derive default; that reopens the image-set url leak (regression-tested via
  security_audit_tests `image_set_with_nested_url...`).
- Value-guard dispatch subtlety: with `TOKENS` requested, `TokenOrValue::Url/Var/Env` hit
  `visit_token` first, so the routing there is required.
